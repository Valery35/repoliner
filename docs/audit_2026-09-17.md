# Проверка архивов модулей Информ++, 17.09.2026

Проверялись архивы из `Dropbox\ИИ`, собранные в реестр Repoliner:
Geoconstructor 1.17.1, Гидронаблюдения 0.3.7, Мониторинг рассолов 0.10.1,
Isoliner 5.13.13 (выгрузочный), Isoliner3D 1.3.1, Topoliner 0.12.7.

Чем проверялось:
- `python tools/audit_archive.py <архив>` (поля metadata.txt, диапазон
  QGIS, мусор, запреты сканера каталога, места для Qt6);
- `bandit -r <модуль> -x <модуль>/tests,<модуль>/libs`;
- живой прогон реестра в QGIS 4.0.3.

Находки Qt6 эвристические. Это список мест для просмотра, а не
доказанные ошибки.

## Geoconstructor 1.17.1

1. `basemaps.py:18` импортирует `xml.etree.ElementTree`. Каталог
   plugins.qgis.org такой архив отклонит. Замена - разборщик
   `xmlparse.py` из Repoliner (тот же, что в Isoliner), он читает
   `.qlr` без модулей xml.
2. 22 места `except Exception: pass` (bandit B110): `plugin.py`,
   `trace.py`, `db_connection.py`, `layer_builder.py`, четыре формы.
   Нужен узкий тип исключения и запись в журнал, либо `# nosec` там,
   где молчание оправдано.
3. В `metadata.txt` пустые `repository` и `tracker`. Каталог требует
   оба адреса.
4. В архиве `tests/` (13 файлов) и нет `LICENSE`. Для каталога нужен
   выгрузочный архив без тестов и с лицензией.
5. Имя файла `geoconstructor_qgis_plugin.zip` не совпадает с папкой
   `geoconstructor`. Установка из ZIP и Repoliner 0.1.1+ это переносят.
   Для единообразия архив лучше называть `geoconstructor.zip`.
6. В настройках по умолчанию имя сервера `BER-GGIS2` и базы `Skvag`.
   Для публичной выкладки это внутренние имена предприятия. Их стоит
   убрать из кода в пресеты.
7. bandit B608 (SQL строкой) - 31 место. Подставляются имя базы из
   настроек и целые идентификаторы, пользовательского текста в запросах
   не видно. Каталог это не блокирует, но при новых запросах значения
   лучше передавать параметрами.

## Гидронаблюдения 0.3.7

1. **В QGIS 4 модуль не виден**: `qgisMaximumVersion` не задан, и QGIS
   считает верхней границей 3.99. Нужно `qgisMaximumVersion=4.99`
   после проверки на QGIS 4. Прямых запретов Qt6 проверка не нашла,
   `QAction` импортируется с запасным вариантом.
2. `core/basemaps.py:18` импортирует `xml.etree.ElementTree` - та же
   замена, что в Geoconstructor.
3. 19 мест B110 (`gui/errors.py`, `gui/*_dialog.py`, `hydromonitor.py`,
   `db/*`, `core/trace.py`, `core/builders.py`).
4. `experimental=True`: модуль виден только при галке экспериментальных
   модулей. Снимать, когда версия стабилизирована.
5. `repository` и `tracker` ведут на `https://github.com/informpp`, а не
   на репозиторий модуля. Каталог ждёт адрес кода самого модуля.
6. `tests/` (20 файлов) в архиве, нет `LICENSE`.
7. Сервер по умолчанию `IRBIS` - внутреннее имя, как в Geoconstructor.

## Мониторинг рассолов 0.10.1

1. **В QGIS 4 модуль не виден** - та же причина, нет
   `qgisMaximumVersion`.
2. **До QGIS 4 нужна правка Qt6**: плоские перечисления
   `Qt.AlignHCenter`, `Qt.AlignTop`, `Qt.WaitCursor` и подобные в
   `gui/ratio_canvas.py` (4 места), `gui/diagram_canvas.py` (5),
   `gui/ternary_canvas.py` (6), `gui/plot_common.py` (3),
   `gui/connection_dialog.py` (2). В Qt6 такое имя отсутствует, и окно
   падает с AttributeError. В модуле уже есть `core/qt_compat.py`,
   константы надо брать оттуда.
3. 6 мест B110 и 1 место B112.
4. `experimental=True`, адреса `repository`/`tracker` общие, `tests/`
   (16 файлов) в архиве, нет `LICENSE` - как в Гидронаблюдениях.

## Isoliner 5.13.13

Архив для каталога чистый. Одно замечание, уже известное: модуль
называется `grid_isolines`, как в официальном каталоге. Своя версия из
реестра видна только на машине с отключённым официальным репозиторием.
Ночной архив `grid_isolines_nightly.zip` с папкой `grid_isolines` из
реестра не ставится, только через «Установить из ZIP».

## Isoliner3D 1.3.1

Архив чистый. `libs/pyqtgraph` импортирует `xml.etree` с меткой
`# nosec` и упоминает PyQt5 внутри своей развилки привязок Qt. Это код
библиотеки, отмечено для сведения. Имя совпадает с каталогом, где
лежит 1.2.0. Пока новая версия не выложена в каталог, из реестра её
видно только при отключённом официальном репозитории.

## Topoliner 0.12.7

Замечаний нет.

## Общие рекомендации

1. Один порядок сборки на все модули: рабочий архив с тестами, имя
   которого равно папке модуля, и выгрузочный для каталога без тестов,
   оба с `LICENSE`. Образец - `scripts/build_zip.py` Repoliner.
2. Перед выкладкой прогонять `tools/audit_archive.py` и bandit.
   Находки из раздела «ошибки» мешают выкладке в каталог или показу
   модуля в QGIS.
3. Для чтения `.qlr` и других XML в Geoconstructor и Гидронаблюдениях
   взять `xmlparse.py`, а не модули xml.
4. Верхнюю границу QGIS задавать явно. Без неё модуль молча пропадает
   в QGIS 4.
5. На шахтных машинах, которые ставят модули только из своего реестра,
   отключить официальный репозиторий в «Модули - Управление и
   установка модулей - Параметры». Иначе каталог перекрывает Isoliner и
   Isoliner3D из реестра.
6. Если реестр будет раздаваться веб-сервером, раздавать отдельную
   папку. В `Dropbox\ИИ` лежат файлы, которые не должны попадать в сеть.
