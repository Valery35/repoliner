# Review of Информ++ plugin archives, 17.09.2026

Archives from `Dropbox\ИИ` collected into the Repoliner registry were
checked: Geoconstructor 1.17.1, Гидронаблюдения 0.3.7, Мониторинг
рассолов 0.10.1, Isoliner 5.13.13 (upload build), Isoliner3D 1.3.1,
Topoliner 0.12.7.

Checked with:
- `python tools/audit_archive.py <archive>` (metadata.txt fields, QGIS
  range, junk files, catalog scanner blockers, places for Qt6),
- `bandit -r <plugin> -x <plugin>/tests,<plugin>/libs`,
- a live run of the registry in QGIS 4.0.3.

The Qt6 findings are heuristic. This is a list of places to review,
not proven errors.

## Geoconstructor 1.17.1

1. `basemaps.py:18` imports `xml.etree.ElementTree`. The
   plugins.qgis.org catalog will reject such an archive. The
   replacement is the `xmlparse.py` parser from Repoliner (the same
   one as in Isoliner), it reads `.qlr` without xml modules.
2. 22 places with `except Exception: pass` (bandit B110): `plugin.py`,
   `trace.py`, `db_connection.py`, `layer_builder.py`, four forms. A
   narrow exception type and a log entry are needed, or `# nosec`
   where the silence is justified.
3. `metadata.txt` has empty `repository` and `tracker`. The catalog
   requires both addresses.
4. The archive holds `tests/` (13 files) and has no `LICENSE`. The
   catalog needs an upload archive without tests and with a license.
5. The file name `geoconstructor_qgis_plugin.zip` does not match the
   folder `geoconstructor`. Install from ZIP and Repoliner 0.1.1+
   tolerate this. For uniformity the archive is better named
   `geoconstructor.zip`.
6. In the default settings the server name is `BER-GGIS2` and the
   database name is `Skvag`. For a public release these are internal
   company names. They should be moved out of the code into presets.
7. bandit B608 (SQL built as a string) - 31 places. The database name
   from the settings and integer identifiers are substituted, no user
   text is visible in the queries. The catalog does not block this,
   but for new queries the values are better passed as parameters.

## Гидронаблюдения 0.3.7

1. **The plugin is not visible in QGIS 4**: `qgisMaximumVersion` is
   not set, and QGIS treats 3.99 as the upper bound.
   `qgisMaximumVersion=4.99` is needed after a check on QGIS 4. The
   review found no direct Qt6 blockers, `QAction` is imported with a
   fallback.
2. `core/basemaps.py:18` imports `xml.etree.ElementTree` - the same
   replacement as in Geoconstructor.
3. 19 places with B110 (`gui/errors.py`, `gui/*_dialog.py`,
   `hydromonitor.py`, `db/*`, `core/trace.py`, `core/builders.py`).
4. `experimental=True`: the plugin is visible only when the
   experimental plugins box is ticked. Remove it once the version is
   stable.
5. `repository` and `tracker` point to `https://github.com/informpp`,
   not to the plugin repository. The catalog expects the address of
   the plugin code itself.
6. `tests/` (20 files) in the archive, no `LICENSE`.
7. The default server `IRBIS` is an internal name, as in
   Geoconstructor.

## Мониторинг рассолов 0.10.1

1. **The plugin is not visible in QGIS 4** - the same cause, no
   `qgisMaximumVersion`.
2. **A Qt6 fix is needed before QGIS 4**: flat enums
   `Qt.AlignHCenter`, `Qt.AlignTop`, `Qt.WaitCursor` and similar in
   `gui/ratio_canvas.py` (4 places), `gui/diagram_canvas.py` (5),
   `gui/ternary_canvas.py` (6), `gui/plot_common.py` (3),
   `gui/connection_dialog.py` (2). In Qt6 such a name does not exist,
   and the window fails with AttributeError. The plugin already has
   `core/qt_compat.py`, the constants should be taken from there.
3. 6 places with B110 and 1 place with B112.
4. `experimental=True`, the `repository`/`tracker` addresses are
   generic, `tests/` (16 files) in the archive, no `LICENSE` - as in
   Гидронаблюдения.

## Isoliner 5.13.13

The catalog archive is clean. One remark, already known: the plugin is
called `grid_isolines`, as in the official catalog. Its own version
from the registry is visible only on a machine with the official
repository turned off. The nightly archive `grid_isolines_nightly.zip`
with the folder `grid_isolines` does not install from the registry,
only through "Install from ZIP".

## Isoliner3D 1.3.1

The archive is clean. `libs/pyqtgraph` imports `xml.etree` with a
`# nosec` marker and mentions PyQt5 inside its own Qt bindings branch.
This is library code, noted for information. The name matches the
catalog, which holds 1.2.0. Until the new version is published in the
catalog, it is visible from the registry only with the official
repository turned off.

## General recommendations

1. One build order for all plugins: a working archive with tests whose
   name equals the plugin folder, and an upload archive for the
   catalog without tests, both with `LICENSE`. The sample is
   `scripts/build_zip.py` in Repoliner.
2. Run `tools/audit_archive.py` and bandit before a release. Findings
   from the "errors" section block the catalog release or the display
   of the plugin in QGIS.
3. For reading `.qlr` and other XML in Geoconstructor and
   Гидронаблюдения take `xmlparse.py`, not the xml modules.
4. Set the upper QGIS bound explicitly. Without it the plugin silently
   disappears in QGIS 4.
5. On mine machines that install plugins only from their own registry,
   turn off the official repository in "Plugins - Manage and Install
   Plugins - Settings". Otherwise the catalog overrides Isoliner and
   Isoliner3D from the registry.
6. If the registry is served by a web server, serve a separate folder.
   `Dropbox\ИИ` holds files that must not reach the network.
